Theme Overview

Both themes maintain the same "confident, quiet" personality. Dark uses pure black (#000) as base with white accents. Light uses soft off-white (#fafafa) with subtle shadows for depth instead of borders.

Dark Theme
Ultra-dark backgrounds with subtle elevation through barely-visible borders.
Light Theme
Soft backgrounds with subtle shadows for depth. Clean and minimal.

6. Design Guidelines
✓ Do
  • → Use CSS variables for all colors
  • → Keep semantic colors consistent across themes
  • → Use shadows in light theme for depth
  • → Use borders in dark theme for separation
  • → Test both themes for accessibility
  • → Respect user's system preference
✕ Don't
  • → Hardcode color values
  • → Use pure white (#fff) in light theme backgrounds
  • → Use heavy shadows in dark theme
  • → Let platform colors bleed into UI
  • → Forget to update both theme definitions
  • → Mix themed and non-themed colors

9. Motion & Transitions

Motion should be fast, subtle, and purposeful. Following Linear/Vercel patterns: instant feedback, smooth reveals, cinematic page transitions.

Fast — 150ms
Hovers, toggles, button states
var(--transition-fast)
Medium — 250ms
Dropdowns, reveals, expansions
var(--transition-medium)
Slow — 400ms
Page transitions, modals, theme switch
var(--transition-slow)
Easing Functions
Default
cubic-bezier(0.4, 0, 0.2, 1)
Most interactions
Ease Out
cubic-bezier(0, 0, 0.2, 1)
Elements entering
Ease In
cubic-bezier(0.4, 0, 1, 1)
Elements exiting
Spring
cubic-bezier(0.175, 0.885, 0.32, 1.275)
Playful bounces (use sparingly)
Motion Rules
  • → Never animate layout properties (width, height) — use transform and opacity only
  • → Stagger animations by 50ms for lists (max 5 items, then fade all)
  • → Reduce motion for users who prefer it: prefers-reduced-motion: reduce
  • → Loading states should animate, but subtly — no spinning logos

Icon Rules
  • → Always use stroke="currentColor" — never hardcode colors
  • → Stroke width: 2px for sizes ≤24px, 1.5px for larger
  • → Never use emojis — they look childish and inconsistent across platforms
  • → Platform icons (Twitter, LinkedIn) are the only exception to monochrome rule
11. Skeleton Loading

Skeletons must match the exact layout they replace. No layout shift on load. The skeleton is a promise of what's coming.

Skeleton Rules
  • → Exact dimensions: Skeleton must match loaded content size — no layout shift
  • → Subtle pulse: Opacity animation 0.4 → 0.7, duration 1.5s, ease-in-out
  • → No spinners: Use skeletons for content, subtle loader only for actions
  • → Stagger appearance: If multiple skeletons, stagger by 100ms
  • → Fast transition out: Fade skeleton → content in 150ms
/* Skeleton base */
.skeleton {
  background: var(--bg-hover);
  border-radius: var(--radius-md);
}

/* Pulse animation */
.skeleton-pulse {
  animation: skeleton-pulse 1.5s ease-in-out infinite;
}

@keyframes skeleton-pulse {
  0%, 100% { opacity: 0.4; }
  50% { opacity: 0.7; }
}
12. Responsive Design

Mobile-first approach. Touch targets minimum 44px. Spacing scales down proportionally, but never below readable thresholds.

Mobile
< 640px
Single column, full-width inputs, bottom nav
Tablet
640px – 1024px
Two columns possible, side nav appears
Desktop
1024px – 1280px
Full layout, sidebar + content + preview
Wide
> 1280px
Max-width container, generous margins
Responsive Rules
Touch Targets
Minimum 44×44px for all interactive elements on touch devices
Spacing
Use --space-4 (16px) minimum padding on mobile, scale up on larger screens
Typography
Body text stays 14px. Headings can scale: 28px mobile → 36px desktop
Layout Shifts
Stack columns on mobile, never horizontal scroll for content
/* Breakpoint mixins (Tailwind-style) */
--breakpoint-sm: 640px;   /* @media (min-width: 640px) */
--breakpoint-md: 768px;   /* @media (min-width: 768px) */

Chart Rules
  • → Grid lines use var(--border-subtle) — almost invisible
  • → Axis labels use var(--text-muted), 11px, uppercase
  • → Data labels use var(--text-secondary)
  • → Hover states: show tooltip with value, highlight data point
  • → No gradients or fills — line charts preferred, area charts with 10% opacity fill max
  • → Animate data on load: draw lines left-to-right, 400ms duration
